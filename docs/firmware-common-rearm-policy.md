# 碰撞事件共同解除規則與模型 JSON 配合事項

日期：2026-09-30

狀態：跨專案變更需求紀錄；尚未實作。使用者要求將 env_sensing 討論中確認的需求寫入模型 JSON 產生工具專案。本文件供後續整合正式 SPEC，不代表既有 SPEC 已修訂、程式已完成或模型已重新驗證。

對應專案：dual_imu_collision_studio。

相關規格：[SPEC-0039 — Software model parameter export for ESP32](../specs/SPEC-0039-model-parameter-export.md)。該規格目前包含既有模型解除參數的匯出契約，實作前需依生命週期整合本次變更；保留既有進行中的修改。

## 已確認的跨專案決定

1. 碰撞模型負責判斷方法，提供判斷值、對應門檻與結果；共同鎖定與解除行為由碰撞模組管理，不由各模型分別決定。
2. 所有碰撞模式的共同解除比例固定為 **0.8**。
3. 所有碰撞模式須連續低於解除門檻 **50 ms**，才允許再次觸發。
4. 解除門檻 = 觸發門檻 × 0.8；觸發後鎖定，持續超限不重複發送事件。
5. 解除計時期間，判斷值回到解除門檻或以上時重新計時。不得在模型內及共同事件管理層各做一次鎖定。
6. MaxAbs 與 L2Norm 等計分方法仍由模型決定；本次不改變模型權重、殘差正規化、計分模式或學習方法。
7. env_sensing 新版模型載入程式接受舊 JSON，但忽略 `detector.release_ratio` 與 `detector.release_quiet_time_s`。這兩欄不再必填，不再驗證其參數型別或數值範圍；JSON 本身仍須語法正確，其他參數照常驗證。
8. 上述韌體修改尚未完成。不能把這份文件當成現有裝置已支援新契約的證據。

## 模型產生工具需要配合的範圍

### JSON 匯出與介面

- 將模型參數與部署端共同事件政策分開，不再把這兩個解除值描述成能控制新版韌體行為的模型參數。
- 新版匯出格式建議不再輸出這兩個欄位；是否保留舊韌體相容匯出模式，須在正式 SPEC 整合時定案。
- 移除新版部署匯出對這兩欄有效值的依賴；保留其他模型完整性、數值有效性與匯出資格檢查。
- 若相關操作介面提供解除值設定，部署目標應清楚呈現固定政策 0.8／50 ms，不可使使用者誤認任意設定會套用至新版韌體。
- 不因本需求刪除其他用途的歷史 Profile、訓練或回放能力。

### 回放與匯出資格

- 用來主張新版裝置事件行為一致的回放／資格驗證，必須使用相同的共同解除政策。
- 舊資格紀錄若在不同解除比例或時間下產生，不能直接宣稱它已驗證新政策下的觸發次數與時點。需要依既有資格管理流程重新驗證相關事件結果。
- 這不代表一律重新訓練模型；模型數值與事件狀態機的驗證影響應分開評估。
- 匯出內容參與 execution snapshot identity／hash 的計算；移除欄位後必須依正式 identity 規則重新計算，不得沿用舊內容的 hash。

## 相容性與尚需定案事項

- 現有 env_sensing 載入器仍要求兩個欄位有效，因此移除欄位的新 JSON 不能直接宣稱可供舊韌體載入；需協調韌體版本或明確提供相容模式。
- 舊模型匯入、專案還原、歷史回放與部署回放的用途不同，不能全域刪除同名欄位來代替契約整合。
- 尚需定案：新版 JSON 是否省略欄位或過渡保留、舊韌體相容範圍、歷史資格標記與重新驗證流程、UI 呈現及契約版本策略。
- 不包含 PC PUB_EVENT 接收／顯示功能；那是另一個上位機接收端的修改範圍。

## 預期驗證

- 覆蓋舊 JSON 含這兩欄、新 JSON 不含這兩欄的相容情境；明確區分新舊韌體能力。
- 新韌體對這兩欄不同值、缺省或不同合法 JSON 型別均忽略，其他 JSON 驗證維持有效；此項由韌體專案驗證。
- 部署回放以固定 0.8／50 ms 驗證：單次觸發、持續超限不重複、低於解除門檻不足 50 ms 不重新啟用、解除計時中斷歸零、重新啟用後可再次觸發。
- 相關不同計分模式遵守相同解除政策；不要求不同計分模式得到相同分數或相同觸發結果。
- 匯出身份、資格紀錄與實際執行政策一致；保留原有模型匯出及回放的適用回歸檢查。
