# 開啟專案直接還原完整 Qualification 結果

## Problem
已完成 Training 的 FIR 專案開啟時會再次逐模型計算 score 與 Qualification，180 秒有界診斷仍在第一個模型。原檔已保存模型／條件層級延遲、模型 robustness、條件計數與資格摘要，沒有保存完整逐錄製／逐碰撞明細、SNR 或逐點 score。可查的 9/21 與 10/6 Git 版本亦有同步開啟 Qualification，因此本方案不宣稱已定位 SPEC-0043／0044 的效能回歸原因。使用者已採用保存完整判定明細、指標與有效性證據、不保存全部 score 的方向。

## Solution
Qualification 完成時保留其不可變結果，儲存專案時將完整結果及版本化身份證據與模型一起原子寫入。Open 只驗證文件、來源及結果綁定，再還原模型與明細，不呼叫 Training、Qualification 或全量 score replay。舊檔可開啟已有摘要；未保存明細顯示「未儲存／N/A」，不自動補算或強制重訓。沿用既有 Start Training、驗證與 Save Project 操作，不新增按鈕或自動儲存。逐點重播及 CSV 匯出維持既有按需計算，不能因保存摘要就宣稱它們完全免計算。

## User Stories
- 使用者完成訓練與驗證並儲存後，重開可直接看到相同 Qualification 結果。
- 使用者開啟舊 FIR 專案時可使用已存模型與摘要，不必為缺少 SNR 或明細重新 Training。
- 使用者可區分有效目前資格、歷史結果與缺少資料；不能把過期證據當作新版 PASS。

### Actual/intended edges and parent mappings
現況 Open：studio_application → project_session／reader → learning_qualification.qualify_model → replay。建議 Open 移除 Qualification 執行邊，保留模型／結果型別映射及完整性驗證。Training → Learning 計算、Save → project_session → file adapter 保持。上述 L1 parent 皆為 studio_application，無跨 parent 新邊。

### Description Views impact
實作時只更新 architecture/designs 中 studio_application、project_session、learning_qualification、manage-project Flow、相關 Type／State Catalog 與演算法記錄。移除 Open 重算逐檔證據的既有描述，加入完整結果保存、惰性恢復與歷史明細缺失分支。透過 architecture_cli.py render 生成 manifest／Description Views，不能手改生成檔。既有 ADR 仍 proposed；無需以例外放寬規則，也不能自行接受 ADR。

## Algorithm impact
FIR／MLP／self-IMU 數學、150ms 判定窗與 0.8／50ms 事件規則不變。完整事件結果擷取、版本化還原與身份失效屬 data-dependent algorithm-bearing features：由 learning_qualification 與 project_session／studio_application 分別擁有。實作前在 authored architecture 中記錄 Algorithm Design Record，列出順序、null／缺資料處理、索引／計數一致性與 hash 輸入。採用現有實際判定值與確定性身份驗證，不能以重播補算作 Open fallback。純 JSON 原子 I/O 沿既有演算法，無新調參／近似計算。

## Execution efficiency impact
不改 worker 數、Task／優先序／核心配置或硬／軟即時排程，也不改 Training execution profile。新持久資料按保留模型×錄製檔／事件數增長，不按每個取樣點存陣列；完整結果會增加少量結構資料，但實際大小及 Save 成本待量測，不承諾固定大小。Open 仍需來源檢查與資料解析，可能仍暫停 UI；CSV 重複解析及背景載入不在本範圍。

## Flow execution impact
舊流程有界觀察：來源主要還原100.51秒、dataset重建48.61秒，149.12秒進第一模型Qualification，180秒仍未完成；不是完整載入時間或統計 SLO，也不是 SPEC-0043／0044 回歸證明。
建議 Training／Qualification → 完整結果保留 → 使用者 Save → 原子文件；Open → JSON與來源驗證 → 模型／結果恢復 → 證據綁定檢查 → commit。成本結論僅為 estimated：移除 Open 的全量驗證與 replay 階段；實際 Open／Save 耗時、記憶體與大小依 AC-005 calibrated／validated 後才可宣稱改善幅度。逐點 Replay／CSV 另依既有要求計算，不承諾免計算。

## Evolution impact
新增模型家族只擴充其結果映射與型別驗證；政策升級保留歷史結果並使目前資格失效，不在 Open 自動遷移驗證；新結果欄位需獨立 schema 相容與缺欄位測試。新版必須讀舊檔；舊程式讀新格式的能力須另測，不能保證。新保存區增加 validator、round-trip 與身份失效回歸成本，維持來源外部引用而不嵌入波形。

## Alternatives

## Out of Scope
